# Documentation overhaul: first pass

## Editorial direction after the interview

The intended reader is AI-fluent without necessarily being an engineer. They
recognize harnesses and have used agent apps, but prefer a comfortable graphical
workspace and do not need Git or terminal workflows foregrounded. Research,
planning, and curated data are useful examples alongside software development.

Lead with “The workspace for all your harnesses.” Name all eight, then explain
the shared root within each workspace and centrally saved transcripts. Local
and remote workspaces have separate files; their conversations appear together
in the Mac app's SQLite store. “Work saved centrally” means transcripts and app
records, not every file generated by an agent.

Remote workspaces, panels, notes, and consolidated usage support that core story.
Keep Calendar, database folders, Library, and Cron Jobs brief while they evolve.
Describe agent-driven note/artifact workflows as experimental. The broader
workspace-history CLI remains in development (PR40 was still open when this
revision was written); do not imply universal agent access to saved history or
cross-harness native session portability is already available.

Use warm, direct language and enough explanation to make the architecture useful
to a reader. Present lightweight performance as a design aim, not a benchmark.
No Woven Matter account is required; users bring their provider access. Describe
permissions by purpose. The first task should use a familiar harness and an
existing account, with Codex suitable for a later example walkthrough.

The [original interview questions](interview.md) are retained as background.
The README now incorporates the user's answers and subsequent value-proposition
brain dump; the next step is refining that copy together.
